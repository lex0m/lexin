# 乐信（lexin）

微信的 Xposed / LSPosed 模块。界面美化 + 几个实用功能，全部只在本机生效。

- 包名：`io.github.lex0m.lexin`
- 版本：**v1.1**（versionCode 3）
- 作者：lex
- 协议：MIT
- 语言：纯 Java（无 Gradle，aapt2 + javac + R8 + apksigner 直接构建）

## 这一版的三个主力功能

### 一、消息防撤回（双向）

别人撤回的消息**原样留在聊天里**，不会被换成「xxx撤回了一条消息」。

原理是抹掉微信那条撤回指令（sysmsg 里的 `$type`）—— 指令不成立，微信就不去改写原消息。
不发请求、不改上行报文，服务端那边什么都不知道。

被撤回的消息会标出来：气泡压暗一点，**气泡正下方**贴一个小胶囊写「对方撤回」。
标签画在行的 overlay 上（不参与布局、不挤压气泡），位置每次重排都重新量一次，
所以切后台回来也不会跑位。自己撤回不贴标签（微信本来就有提示，再叠一个是两个提示打架）。

撤回记录只存「会话 + 消息id + 方向」，不存消息内容；上限 800 条（LRU），存在微信自己的配置里。

### 二、运动步数修改（三种模式，分开的）

| 模式 | 效果 |
| --- | --- |
| **直接指定步数** | 今天就是那个数，立刻生效（填 12000，微信运动就读到 12000） |
| **自动增加** | 每小时自动加 N 步，随时间平滑涨，像真在走路 |
| **倍率** | 按真实步数放大（1.2 ~ 5 倍） |

都带**额外步数上限**（默认 20000，可选 5000 ~ 80000），超了停在上限，不会出现一眼假的数字。

**走外部通道，不碰微信的数据接口：**

1. 优先挂在**微信自己算出来的「今天步数」**上 —— 各家手机的步数来源不一样（小米读 MIUI 的
   content provider、其它品牌多半读系统计步器），微信内部已经做过适配，挂在它的结果上就与品牌无关，
   换手机不用改规则；
2. 挂不上就退回**框架传感器层**（`SystemSensorManager$SensorEventQueue.dispatchSensorEvent`），
   在数据分发出去之前改掉累计值，微信一行代码都不碰；
3. 微信自己听计步器的两条路（`MMSportStepDetector` / `PushSportStepDetector`）也一起挂上；
4. 只在**主进程**装（`:push` 等进程跳过），避免同一份数据被改两遍。

这里有个坑写出来给后来人：微信算的是「今天的累计 − 今天第一次读到的累计」，是个**差值**。
给累计值加固定偏移会被减掉、等于没改 —— 所以「直接指定」走的是**一次性注入增量**，不是加常数。

### 三、去广告

| 位置 | 做法 |
| --- | --- |
| 朋友圈信息流 | 掐掉广告对象的构造（`plugin.sns.storage.ADInfo`），条目录不进时间线 |
| 小程序开屏 | 广告判定一律答「否」 |
| 开屏广告 | 同上，挂在判定点上 |

只拦本地决策点，不改任何网络请求。三处归**同一个开关**管（面板里的「屏蔽广告位」）。

## 其它功能

- **朋友圈保留**：对方删掉的评论和动态，本机留副本（只拦朋友圈表上的 DELETE，其它 SQL 原样放行）
- **解除扫码限制**：相册选图、长按图片识别二维码不再受微信那层限制（按「相机」场景处理）
- **自动查看原图**：浏览图片时自动切原图
- **放宽本地限制**：表情包数量、消息多选、状态字数上限
- **骰子 / 猜拳自选**：长按表情面板里的骰子或猜拳，弹框选点数/出拳，也可以保持随机
- **界面美化**：全屏背景（透明度 / 五种缩放 / 自定义裁剪）、列表卡片化、聊天条独立成卡（配图、圆角、内缩、模糊）、毛玻璃、状态栏与顶部栏跟随背景
- **设置面板顶部**：每日一言（每次打开换一句，诗词/古籍/技术/幽默混着来）+ 当前登录微信的头像与昵称
- **免责声明**：首次打开强制阅读两秒（含禁止国内网络传播条款），读过不再出现

## 装

1. 装 `dist/lexin.apk`
2. LSPosed 里勾选「乐信」，作用域勾微信
3. 强行停止微信再打开

## 打开设置面板（三种都行）

1. **LSPosed → 模块 → 乐信 → 右下角 ▶ 按钮**
2. 桌面「乐信」图标
3. 微信里：我 → 设置 → 更多 → 关怀模式 → **长按「开启」**（隐藏入口）

## 构建

不用 Gradle，JDK 21 + aapt2 + R8 + apksigner：

```sh
PREFIX=<jdk/aapt2/apksigner 前缀> sh build.sh    # 产物 dist/lexin.apk
```

签名密钥放 `keystore/`（已 gitignore，不入库）；R8 混淆规则见 `proguard-rules.pro`。

## 微信更新 / 换手机了怎么办

模块自己会适配，不用改代码。锚点解析是四级回退，每级都带指纹校验（宁可少一个功能，也不挂错类）：

```
功能代码只说要「撤回解析器」
        ↓
 1) assets/anchors.json 里当前版本精确命中
 2) 邻近版本（同 8.0.x，从近到远）
 3) 本机学习缓存（按 versionCode 存，换版本自动作废）
 4) 运行时扫微信 dex —— 三层特征：类名包名 / 方法内字符串常量 / 方法签名
 5) 都不行 → 该功能安静跳过，面板里显示「未适配」
```

扫到的结果写回本机缓存，下次启动零成本。表里没有的微信版本也能用，只是首次可能要重启一次微信。

已实测生成版本表的微信版本：**8.0.72 / 8.0.74 / 8.0.76 / 8.0.77 / 8.0.78（本机实测 9/9 功能生效）/ 8.0.79**。

给新版本补表（可选）：

```sh
python3 tools/gen-anchors.py . 8.0.80=/path/weixin8080.apk   # 约 25 秒/版本，直接解析 dex 不反编译
sh build.sh                                                  # 表会打进 APK
```

## 隐蔽性

- 发布版**不写任何日志**（`Log.d` 在正式构建里是空实现）
- 不在微信目录新建文件：配置写进微信自己的 `shared_prefs/com.tencent.mm_preferences`，
  键名统一 `ap_+hashCode`，混在微信自己的几百个键里
- 挂到微信视图树上的只有框架类（撤回标签是 `BitmapDrawable`）
- 框架级兜底 hook 只在必要的时候才挂
- 不改任何上行报文
